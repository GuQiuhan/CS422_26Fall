# Lesson 1.20 exercises

## Exercise (Choosing a backend)

```
kompile lesson-20.k                                 # LLVM backend (default)
krun -cPGM=0 --output kore --directory .

kompile lesson-20.k --backend haskell --output-dir haskell-kompiled
# add --no-haskell-binary on arm64 macOS if it crashes
krun -cPGM=0 --definition haskell-kompiled
```

Both should converge to `100` (the rule fires while `I <Int 100`, so it
counts up from 0 to 100 and then gets stuck, since there's no other rule
and `100 <Int 100` is false). The LLVM backend reaches this by direct
compiled execution; the Haskell backend reaches the same fixpoint by
interpreting the IR, more slowly but via the same term-rewriting
semantics, so the final configurations should agree.

## Exercise 1 (bottom of lesson)

Reusing the minilang from Lesson 1.18, Exercise 2
(`../18_equality_and_conditionals/lesson-18-ex2-minilang-if.k`):

```
kompile ../18_equality_and_conditionals/lesson-18-ex2-minilang-if.k \
  --main-module LESSON-18-EX2-MINILANG-IF --syntax-module LESSON-18-EX2-MINILANG-IF-SYNTAX \
  --output-dir minilang-llvm-kompiled
krun ../18_equality_and_conditionals/minilang-if.pgm --definition minilang-llvm-kompiled

kompile ../18_equality_and_conditionals/lesson-18-ex2-minilang-if.k \
  --main-module LESSON-18-EX2-MINILANG-IF --syntax-module LESSON-18-EX2-MINILANG-IF-SYNTAX \
  --backend haskell --output-dir minilang-haskell-kompiled
krun ../18_equality_and_conditionals/minilang-if.pgm --definition minilang-haskell-kompiled
```

Since this definition is deterministic (every step matches at most one
rule for any reachable configuration), both backends should produce the
identical final `<T>` configuration. If they ever diverged, the
suggested next step would be `krun --search` on the LLVM backend to see
whether there is in fact hidden nondeterminism (a configuration matching
more than one top-level rule) that the two backends are resolving
differently.
