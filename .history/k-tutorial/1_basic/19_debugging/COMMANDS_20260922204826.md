# Exercise 1: GDB/LLDB walkthrough

```
kompile lesson-19-ex1-minilang-if-debug.k --enable-llvm-debug
krun minilang-if-debug.pgm --debugger
```

## 1. Breakpoint on `isKResult`, observe state

GDB:
```
(gdb) break LESSON-19-EX1-MINILANG-IF-DEBUG.is-int.rhs
(gdb) run
```
LLDB:
```
(lldb) breakpoint set --name LESSON-19-EX1-MINILANG-IF-DEBUG.is-int.rhs
(lldb) run
```
This stops the first time `isKResult` is checked against an `Int` (e.g. right after `5` is heated for `x = 5;`). The substitution shown is the argument passed to `isKResult`.

## 2. Breakpoint on the addition rule, run until hit

GDB:
```
(gdb) break LESSON-19-EX1-MINILANG-IF-DEBUG.addition.rhs
(gdb) run
```
LLDB:
```
(lldb) breakpoint set --name LESSON-19-EX1-MINILANG-IF-DEBUG.addition.rhs
(lldb) run
```
This stops when `x + 3` (both operands already `Int`) is about to be rewritten by the `[addition]` rule -- i.e. `y = x + 3;` after `x` has been looked up to `5`.

## 3. Step until `+` is at the top of `<k>`, then `k match` the subtraction rule

```
(gdb) k start
(gdb) k step        # repeat, or `k step N`, until <k> shows `5 + 3 ~> ...`
(gdb) k match LESSON-19-EX1-MINILANG-IF-DEBUG.subtraction subject
```

Expected output (to put it simply):
```
Subject:
5 + 3
does not match pattern:
_ - _
```

This is because the top symbol of the current term is `+` (`Exp "+" Exp`), while the `[subtraction]` rule's pattern is rooted at the different constructor `Exp "-" Exp` -- the two productions are distinct, so no amount of matching on the operands can make them equal.
